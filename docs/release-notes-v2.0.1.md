# 声浪 SongWave v2.0.1

> ⚠️ **重要修复版**：修复了「打开后什么都点不动 / 音源导不进 / 播不了」的严重问题

## 🐞 修复的问题

### 1. 音源脚本会把主进程打崩（最严重）
部分音源脚本（例如名称含 `latest` 的那类）在加载后会在自己的 Promise 链（`.finally`）里抛错。
Node 默认会把「未处理的 Promise 拒绝」升级为**进程中止**，于是：
- 窗口还开着，但**主进程已死** → 所有 IPC 失效
- 表现：**导入弹不出结果、搜索/播放毫无反应**（点什么都像坏的）

修复：
- 运行时内置**防崩护栏**（`uncaughtException` / `unhandledRejection` 只记录日志，不再中止进程）
- `request` 回调里的异常就地吞掉并记录，不再逃逸
- 沙箱补齐 `window.addEventListener` / `document` / `setInterval` 等浏览器 API（不少脚本会用它们注册全局错误处理，缺了就一加载就抛错）

### 2. 一个慢/坏脚本拖死整个界面
原来**串行**加载所有音源，每个失败脚本要等满 30 秒超时。装了 6 个源时首屏要等 **30 秒~数分钟**。

修复：
- **并行加载**（总耗时 = 最慢那个，而不是累加）
- 默认超时 30s → **8s**（可用环境变量 `SONGWAVE_SOURCE_INIT_TIMEOUT` 调大）
- **失败的音源 10 分钟内不再重试**（点面板 ↻ 可强制重试）
- **导入不再阻塞**：导入后立即返回，后台刷新状态

实测（本机 6 个源，其中 2 个是坏的）：**加载用时 623ms**，4 个可用源正常就绪。

### 3. 托盘创建失败
`main.js` 漏了 `Tray / Menu / nativeImage` 的引入，托盘一直创建失败。已修复。

### 4. 新增运行日志（便于排查）
打包版看不到控制台，现在会写日志文件：

```
%APPDATA%\声浪 SongWave\songwave.log
```

包含：启动版本/Electron 版本、音源目录、加载耗时与每个音源的成功/失败原因、IPC 失败堆栈、被忽略的脚本异常。反馈问题时附上这个文件即可。

## 📦 安装

1. 下载 `SongWave-Setup-2.0.1.exe`
2. 双击安装（未签名，SmartScreen → 更多信息 → 仍要运行）
3. 若之前装过旧版，直接覆盖安装即可；配置与音源列表会保留

## 💡 如果你之前遇到「点了没反应」

装上本版后：
1. 打开面板 ⚙ → **音源管理**，会看到每个源的 `ok/失败原因`
2. 对失败的源（如 `latest`、`独家音源`、`六音音源`）：
   - **删掉**（✕）或**停用**（取消勾选），或
   - 点 **↻** 强制重试（需要联网）
3. 只要留下能用的源（如 `flower` / `野花`），QQ/酷狗/酷我/咪咕 就能取链播放

## 🧪 质量

**13 套测试、352 条断言全绿**，新增：
- `test:resilience` —— 坏脚本不得打崩进程、不得拖死加载、失败源不阻断可用源（含「异步抛错的脚本」「永不声明能力的脚本」「使用浏览器 API 的脚本」三类）
- `test:preload` —— preload 暴露的接口 vs 渲染层调用的接口一致性（防止「调用了却没暴露」导致功能静默失效）
