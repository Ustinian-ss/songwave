# 声浪 SongWave v2.0.9

你问的"**LX 能播、我这里不行**"，查到底了 —— 答案不在网络，也不在调用方式，而在**缓存**。

## 一、先给结论（都有实测数据）

1. **LX 播的是它自己的「已解析地址缓存」，不是现取的。**
   我从 LX 的本地数据库 `lx.data.db`（`music_url` 表）里读出了它为你正在播的那首歌存的地址：

   ```
   kw_239211505_128k → http://car-er.kuwo.cn/b7c88d971d368e2248a52000749f87c5/6ab7de70/resource/30106/trackmedia/M5000044Fd2s1LB6MJ.mp3
   ```

   这条地址**现在仍然 HTTP 200**（腾讯 COS，2022 年的文件）→ 完整版 232 秒。所以 LX 即使源脚本失效也照播不误。

2. **你那个 flower 源脚本的后端，对同一个 rid 是 404。**
   我把 LX 安装目录里的运行时实现（`resources/app.asar → dist/user-api-preload.js`）挖出来，逐字对比了我的实现：
   `lx.request` 的参数、回调 `(err, resp, body)`、`resp.body` 先 `JSON.parse`、`currentScriptInfo` 字段、`version:"2.0.0"`、`env:"desktop"`
   —— **全部一致**。也就是说我发的请求和 LX 会发的请求是同一个：

   ```
   GET http://97.64.37.235/flower/v1/url/kw/239211505/music
   headers: {User-Agent: lx-music/desktop, ver: 2.0.0, source-ver: 1, tag: <hex>}
   → 404 Not Found
   ```

   顺带把两边脚本也对比了：LX 里存的 `野花🌷 v1` 和我下载/导入的 `latest.js` **md5 完全相同**（`28a6d8f0…`）。
   结论：源脚本后端已经挂了，LX 是靠缓存活着。

## 二、本次补上的能力（这才是你真正需要的）

### 1. 已解析播放地址缓存

- **取链顺序**：缓存 → 音源脚本（逐个候选）→ 内置原生取链；
- 命中缓存会**先验证是不是真音频**（只取响应头，几百毫秒），失效就剔除并重新取链；
- **取链成功后自动写回缓存** —— 以后同一个源挂了也不影响这首歌再播。

### 2. 「导入已解析地址」按钮（音源管理面板）

一键读取其它播放器（LX Music）数据库里已经解析好的地址：

```
LX Music 709 条（sqlite）
→ 缓存共 709 条：网易云 529、酷我 164、QQ 125、酷狗 16 …
```

实现上做了两件不用依赖第三方库的事：

- **极简 SQLite 只读读取器**（`src/sqlite-lite.js`）：页头/varint/serial-type/b-tree 遍历 + **WAL 回放**（带 salt 校验），还处理了"第 1 页前 100 字节是文件头、而 cell 偏移相对页首"这个坑；
- **音源代码自动映射**（`kuwo↔kw`、`netease↔wy`、`qq↔tx`、`kugou↔kg`、`migu↔mg`），否则导入进来也命不中。

**实测效果**（同一首「野火 - 戾格」）：

| | 取链结果 |
| --- | --- |
| 修复前 | `native:kuwo` → `kw-bj.kuwo.cn/…/nf/resource/n1/…` **11 秒试听** |
| 导入缓存后 | `cache(lx)` → `car-er.kuwo.cn/…/trackmedia/M5000044Fd2s1LB6MJ.mp3` **完整 232 秒** |

### 3. 音源体检（延续 v2.0.8）

面板上一键逐个真取链，直接告诉你哪个脚本还能用：

```
❌ 野花🌷 v1.0.0：ENOTFOUND flower.tempmusics.tk     ← 旧版域名已废
❌ 六音音源 v1.2.1：HTTP 403
❌ 野花🌷 v1：HTTP 404                                 ← 后端已挂
```

## 三、怎么用（30 秒）

1. 打开「设置 / 音源管理」面板 → 点 **导入已解析地址**（看到"新增 709 条"即可）；
2. 回到搜索，正常播放 —— 之前 LX 播过的歌现在都能完整播；
3. 之后新解析成功的歌会自动进缓存，越用越稳。

> 注意：如果一首歌**任何源都没解析成功过**（缓存里也没有），那它仍然只能拿到平台自己给的试听片段 —— 这是版权侧的限制，不是播放器的问题。
